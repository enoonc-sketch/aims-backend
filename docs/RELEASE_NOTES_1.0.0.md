# AIMS 1.0.0 版本发布说明

- **版本**：1.0.0（产品化正式版）
- **发布类型**：首个可选交付的正式版本（替代 0.6.0 原型）
- **基线提交**：`fac8dac`（阶段 0 审计前快照）→ 1.0.0 阶段提交链
- **源码包**：`AIMS-1.0.0-Source.zip`
- **安装包**：`AIMS-1.0.0-x64-Setup.exe`（由 `build\build_x64.ps1` 在 Windows 构建机产出）

---

## 一、本次发布的定位

0.6.0 已经"能跑"，但作为交付产品有四个硬伤：**访问控制没收口**（70 个 GET 无认证、默认弱口令）、**依赖有已知漏洞**、**没有数据生命周期管理**、**部分界面是假数据/占位按钮**。1.0.0 把这四项全部处理掉，并补齐了独立运行、数据库隔离、AI 模型生命周期、模板中心、启动器、安装包、正式测试。

按计划书 0→9 阶段推进，每阶段独立提交、独立回归。

## 三、功能与产品化

### 3.1 独立运行

- 后端 EXE 改为 **Windows GUI 子系统**：双击不出现任何 CMD/控制台窗口
- 全部子进程（taskkill / schtasks / powershell / Edge / pip）补 `CREATE_NO_WINDOW`
- 备份快捷方式改由 `run-hidden.vbs` 以窗口样式 0 启动（`-WindowStyle Hidden` 仍会闪一下），完成后弹原生窗口告知结果
- 保留开发调试：`AIMS_DEBUG_CONSOLE=1` 或开始菜单「AIMS 调试模式（控制台）」
- 内置 PostgreSQL + pgvector + Python 运行时，目标机零依赖、可断网

### 3.2 可靠启动与崩溃恢复

- 启动器看门狗覆盖**所有界面模式**（此前只在 `--headless` 排障模式监控）：
  后端退出 → 写 error 日志（退出码 + 日志路径）→ 有限次自动重启（1.5 s / 3 s / 6 s 退避）→ 连续 3 次失败弹窗告知并停止重试
- 托盘「重启服务」复用同一线程，不会叠加多个看门狗
- 危险降级防护：数据库程序在但数据目录缺失时**明确报错**，不再静默回退空库

### 3.3 AI 模型生命周期

- 卸载（释放内存/显存，文件保留）与删除（超管 + `?confirm=true` + 激活中拒绝 + 规则包拒绝 + 目录外路径拒绝）分离
- 本地 GGUF 扫描导入：魔数校验 + SHA-256 + 幂等登记
- AI 引擎信息卡：真实探测后端、模型数、当前激活模型（不是固定文案）

### 3.4 模板中心

- 真实模板列表/分类/创建/编辑/版本/回退/导入导出/收藏/应用
- 权限：编辑/删除/回退仅**创建者或管理员**；系统内置模板改名/改分类/删除对所有人 403
- 导入上限统一 64 MB；导出为 `.aimstpl`（含 `manifest.json`）
- 修复 `tplLoadCategories` 的 `ReferenceError`（catch 分支引用未定义变量）

### 3.5 业务界面

- 新增**报警中心**页面（筛选/确认/解除/规则页签）
- 系统页新增**用户 / 审计 / 组件**三个页签（组件信息取真实版本、大小、扩展状态）
- 故障 PDF 改为**真实解析**（`pypdf` 提取文本 + 标签正则，识别设备/测点/时间），不再用假数据
- 未登录首屏不再向受保护接口发请求（首屏 401 从 3 个降为 0），登录后自动切到数据库真实数据
- 演示数据横幅、KPI 空库显示 0 而非随机数

### 3.6 数据可靠性

- 测点导入幂等：`INSERT ... ON CONFLICT DO UPDATE`，重复导入不再 500（并修掉由此暴露的 pandas 标量访问性能问题）
- 备份/恢复：`pg_dump -Fc` + SHA-256 元数据，恢复前自动备份当前数据
- 升级：先备份 → 保留旧程序副本 → 只增不删的结构升级 → 自检 → 失败回滚
- 卸载：默认保留全部用户数据，删除需二次确认且先备份

## 六、已知限制（如实说明）

1. **Windows 实机构建与安装验收未在本环境完成**（开发环境为 Linux）：`build_x64.ps1`、ISCC 编译、干净 Win11 安装→启动→升级→卸载全流程需在 Windows 构建机执行。源码与打包配置已改完并用 15 条静态断言锁死。
2. **安装包未签名**，SmartScreen 会提示未知发布者；需企业代码签名证书。签名流程已内置在构建脚本（设置 `AIMS_SIGN_CERT` 即自动签名+验签，顺序由测试锁死），证书到位即可启用。
3. **ARM64 为仿真模式**（x64 PostgreSQL 经 Prism 运行），性能低于原生约 10–25%，且必须在该实机验收后才能承诺支持。
4. **AI 本地推理需自备模型**：未放 `.gguf` 或未装 llama.cpp 时自动降级为规则引擎（功能不缺失，能力有限）。
5. **未做第三方渗透测试**：安全审计为"已知攻击面 + 自动化回归"层面，建议发布前补一次人工渗透。
6. 生产模式请确认 `APP_ENV=production`（关闭 `/docs` 与 `/openapi.json`）。

## 七、升级注意事项

- 从 0.6.0 升级：数据库结构只增不删，数据保留；`deploy upgrade` 自动补表补列
- 升级前必须有一份当天备份（安装程序会自动做，但建议手工再确认一次）
- 旧版安装包不能覆盖新版（降级保护会警告），回滚请按 `docs/管理员手册.md` 3.3 节操作
- 升级后请重跑 `deploy doctor` 与界面自检 34 项
