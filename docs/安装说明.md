# AIMS 1.0.0 安装说明

面向实施人员。目标：一台**没装过 Python / Node / Docker / PostgreSQL** 的干净 Windows 机器，断网也能装完。

---

## 一、环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 11 x64 | ARM64 见第六节（仿真模式，需如实告知客户） |
| 权限 | 安装需管理员权限 | 注册数据库服务、写 `ProgramData` |
| 磁盘 | ≥ 8 GB 可用 | 程序约 1.2 GB，数据库与模型另计；安装程序预留 500 MB 额外空间 |
| 内存 | ≥ 8 GB | 纯管理端可 4 GB；本地 AI 推理建议 16 GB 起 |
| 网络 | **不需要** | 离线安装包自带 Python 运行时、PostgreSQL、pgvector、AI 引擎 |
| 端口 | 8000（Web 界面）、55432（内置数据库） | 被占用时安装向导会报错并提示改端口 |

**不需要**安装：Python、Node.js、Docker、PostgreSQL、Visual C++ 运行库（均已内置或静态链接）。

---

## 二、安装步骤

1. 把 `AIMS-1.0.0-x64-Setup.exe` 拷到目标机（U 盘/内网共享均可）。
2. 双击运行。若出现"未知发布者"提示：当前版本未做代码签名（见第七节），选择"更多信息 → 仍要运行"。
3. 接受许可协议 → 选择安装位置（默认 `C:\Program Files\AIMS`）。
4. 勾选任务：
   - **创建桌面快捷方式**（推荐）
   - **开机自动启动**（可选，登录后最小化到托盘）
   - **把内置数据库注册为 Windows 服务**（推荐，启动更快、崩溃后可自恢复）
5. 点击安装。安装程序依次执行：
   - 停止可能残留的旧进程
   - 复制程序文件与内置 PostgreSQL
   - `deploy provision`：初始化数据库集群、建库建表（57 张）、启用 pgvector、创建管理员、首份备份
   - `deploy doctor`：安装后健康检查（**不通过不会显示"安装完成"**）
6. 安装完成后勾选"立即启动 AIMS"，或双击桌面快捷方式。

> **不会出现任何 CMD / PowerShell 黑窗**。后台服务由启动器统一管理，日志写到 `C:\ProgramData\AIMS\Logs\`。

### 首次启动会做什么

- 启动内置 PostgreSQL（服务模式或进程模式）
- 校验数据库结构并补齐缺表/缺列（只增不减）
- 启动后端 API（仅监听 `127.0.0.1`，不对外网开放）
- 打开桌面窗口（WebView2）

### 管理员账号

全新安装默认创建管理员账号 `admin`，初始口令 `admin123`。**首次登录后请立即在「系统设置 → 修改密码」中修改口令**。实施人员也可在安装时用 `--admin-password` 自定义初始口令。

## 三、安装后验证

### 3.1 界面自检

「系统 → 诊断」点击"运行自检"，应显示 34/34 通过（真实业务链路：登录、设备、测点、资产、报警、知识库、AI、看板、导入导出、模板、权限、审计）。

### 3.2 命令行自检（排障用）

开始菜单 →「AIMS 诊断报告」，或命令行：

```powershell
& "C:\Program Files\AIMS\AIMS-Backend\AIMS-Backend.exe" deploy --root "C:\Program Files\AIMS" doctor --api-port 8000
```

期望输出 `结论：正常`。常见"提示"（非失败）：

- `应用端口 8000 已被占用` —— AIMS 正在运行，属正常
- `AI 推理引擎：本地推理不可用` —— 未安装 llama.cpp 或未放模型，AI 自动降级为规则引擎，功能不缺失

### 3.3 安全复核

```powershell
python tools\security_audit.py --api http://127.0.0.1:8000 --admin <账号> --admin-password '<口令>'
```

期望 `高危 0 / 中危 0`（详见 `docs/安全审计报告.md`）。

## 四、目录结构

| 路径 | 内容 | 卸载时 |
|---|---|---|
| `C:\Program Files\AIMS` | 程序、内置 PostgreSQL、前端、规则包 | 删除 |
| `C:\ProgramData\AIMS\Database` | 数据库集群 | **保留** |
| `C:\ProgramData\AIMS\Backup` | 备份（`.dump` + `.meta.json`） | **保留** |
| `C:\ProgramData\AIMS\Config` | `aims.env`（连接串、端口）、`secrets.json`（密钥） | **保留** |
| `C:\ProgramData\AIMS\Logs` | 后端日志、安装报告、自检报告、崩溃日志 | **保留** |
| `C:\ProgramData\AIMS\Models` | 本地大模型（`.gguf`） | **保留** |
| `C:\ProgramData\AIMS\Uploads` | 用户上传文件 | **保留** |

> 卸载默认只删程序、保留全部数据；要彻底清理必须显式选择"删除数据"并二次确认（会先自动做一次备份）。

## 五、升级

### 5.1 通过安装包升级（推荐）

直接用新版 `Setup.exe` 覆盖安装：

1. 安装程序检测到已安装版本，若**新版低于已装版本会拦截并警告**（防旧包覆盖新库结构）。
2. 自动停止运行中的 AIMS。
3. **升级前自动备份数据库**（`--reason pre-upgrade`），备份失败会询问是否继续（建议中止）。
4. 把旧程序目录复制到 `rollback\<旧版本>\` 作为回滚副本。
5. 覆盖程序文件 → `deploy upgrade`（只增表/增列/装扩展，**不删数据**）→ `deploy doctor` 自检。
6. 自检不通过时可用回滚副本 + 升级前备份恢复；也可手动执行 `tools\upgrade.ps1` 触发同样的"备份→升级→自检→失败回滚"流程。

### 5.2 只升级结构（不换程序文件）

```powershell
& "C:\Program Files\AIMS\tools\upgrade.ps1"
```

## 六、ARM64 说明（如实告知）

- PostgreSQL 官方**没有** Windows ARM64 原生发行版，pgvector 同样只有 x64 预编译。
- 因此 ARM64 包默认是**仿真模式**：x64 的 PostgreSQL 通过 Windows 11 的 Prism 仿真运行，安装包文件名带 `-emulation`，性能比原生低约 10–25%（AIMS 为单机低并发，瓶颈在 AI 推理与磁盘，影响有限）。
- 若客户自备 ARM64 版 PostgreSQL，可用 `-Native` 构建原生包（`build\build_arm64.ps1 -Native`）。
- **仿真包必须在该 ARM64 实机上完成验收后才能对外承诺"支持 ARM64"**，不得直接把 x64 包说成 ARM64 原生。

## 七、签名与校验和

发布包内 `SHA256SUMS.txt` 列出每个文件的 SHA-256，`release-manifest.json` 记录版本、构建时间、安装包大小与哈希。校验：

```powershell
Get-FileHash .\AIMS-1.0.0-x64-Setup.exe -Algorithm SHA256
# 与 SHA256SUMS.txt 中对应行比对
```

当前版本**未做代码签名**（需企业代码签名证书）。取得证书后，构建脚本已内置签名环节，
不需要手工对每个文件执行 signtool：

```powershell
# 1) 配置证书（只在构建机上设，不要写进仓库或脚本）
$env:AIMS_SIGN_CERT       = 'D:\certs\aims-codesign.pfx'   # 或证书指纹（已导入证书库）
$env:AIMS_SIGN_PASSWORD   = '<pfx 口令>'
$env:AIMS_SIGN_TIMESTAMP  = 'http://timestamp.digicert.com'  # 可选，默认 DigiCert
$env:AIMS_SIGN_REQUIRED   = '1'    # 正式发版：缺配置即中止构建，杜绝"忘签就发"

# 2) 正常构建 + 打包，签名按正确顺序自动完成
.\build\build_x64.ps1          # 先签 AIMS.exe / AIMS-Backend.exe，再编译安装包，最后签 Setup.exe
.\build\package_release.ps1 -Installer .\installer_output\AIMS-1.0.0-x64-Setup.exe

# 3) 复核
Get-AuthenticodeSignature .\release\AIMS-1.0.0\AIMS-1.0.0-x64-Setup.exe | Format-List Status,SignerCertificate
```

顺序是硬要求（脚本用测试锁死）：**主程序先签 → 再编译安装包 → 安装包再签 → 最后生成
`SHA256SUMS.txt`**。签完再改文件会让签名失效、哈希也对不上。若未配置证书，构建照常
完成但会明确打印「本次发行包未签名」，`release-manifest.json` 里 `code_signing.signed`
为 `false`——不假装签过。

## 八、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击快捷方式没反应 | 后端启动失败（数据库未起/端口占用） | 看 `C:\ProgramData\AIMS\Logs\` 与 `aims_crash.log`；运行「AIMS 诊断报告」 |
| 安装最后提示健康检查失败 | 端口冲突、磁盘满、PostgreSQL 无法启动 | 看 `Logs\post-install-doctor.json`，按 `→` 提示处理；修复后重跑安装程序（覆盖安装不动数据） |
| 界面能开但数据空白 | 后端连的是空库（数据目录被改过） | 1.0.0 会在启动时明确报错"数据库程序已就位但数据目录不存在"，按提示确认 `AIMS_DATA_ROOT`；**不会**静默回退到空库 |
| 备份快捷方式点了没反应 | 备份窗口是隐藏的，完成后会弹窗告知结果 | 等弹窗；失败会提示去 `Logs` 看原因 |
| 卸载后重装，数据还在 | 设计如此：卸载默认保留数据 | 需要清空请用"删除数据"选项或手动删除 `C:\ProgramData\AIMS` |
| 想排查后端细节 | 正式版无控制台 | 开始菜单「AIMS 调试模式（控制台）」，或设 `AIMS_DEBUG_CONSOLE=1` 后运行 |
| 系统设置 → Components 提示"登录已失效" | 会话过期/重装后残留旧令牌，或两个页签并发刷新触发整族吊销（1.0.3 已修：并发刷新有宽容窗口 + 前端跨页签协调） | 点弹出的「重新登录」按钮重新登录即可；若反复出现，清浏览器 localStorage（F12 → Application → Local Storage → Clear） |
| 启动失败只弹「Press Enter to exit...」 | 旧版构建的弹窗不带原因（1.0.3 已修复：弹窗正文即真实报错） | 1) 开始菜单「AIMS 调试模式（控制台）」看完整输出；2) 按顺序找 `aims_crash.log`：安装目录 → `安装目录\aims_data` → `%TEMP%`；3) 把日志内容发给维护者 |

### 8.1 启动失败的四步定位法

1. **弹窗即原因**（1.0.3 起）：失败弹窗不再只有「Press Enter to exit...」，
   正文就是启动过程捕获到的报错输出（配置错误、端口占用、崩溃堆栈都会显示），
   点确定后会自动打开诊断报告所在文件夹。
2. **一键自诊断**：在 cmd 里执行安装目录下的

   ```bat
   AIMS-Backend.exe diagnose
   ```

   生成 `aims-diagnose-latest.txt`（在 `Logs\` 或数据目录下），开头就是
   **关键判断**（例如"数据库端口 55432 被别的程序占用"、"数据目录不在预期位置"），
   后面附路径权限、生效配置（口令已脱敏）、数据库状态、各日志尾部。
   **把这个文件发给维护者即可定位问题**，不需要再描述现象。
3. **控制台复现**：开始菜单「AIMS 调试模式（控制台）」会用可见控制台启动后端，
   输出一目了然；也可以在 cmd 里直接运行 `AIMS-Backend.exe`。
4. **崩溃日志**：任何启动异常都会写 `aims_crash.log`，查找顺序为
   安装目录 → `安装目录\aims_data\` → `%TEMP%\aims_crash.log`（安装目录在
   Program Files 下时普通用户无写权限，自动落到后两个位置之一）。

> 自诊断报告里不含任何口令明文：`DATABASE_URL` 的密码段与含
> PASSWORD/SECRET/TOKEN 的变量都已打码，可以放心外发。
