## 四、技术选型说明（计划书第五章）

| 领域 | 计划书候选 | 选定 | 理由 |
|---|---|---|---|
| 桌面界面 | PyWebView / Tauri | **PyWebView** | 零新增工具链、复用现有 Web UI、WebView2 随 Win11 自带、纯 Python 依赖便于 PyInstaller；Tauri 需 Rust 构建链且壳与后端要跨进程通信，收益不抵风险 |
| Python 封装 | Nuitka / PyInstaller | PyInstaller（原项目既有 `build_exe.spec`） | 保持原项目路线，不重写 |
| 后端 | Python + Flask | **FastAPI（事实修正）** | 现有源码即 FastAPI；计划书的"Flask"为笔误，按"不得假设不存在的功能"原则以真实源码为准 |
| 安装程序 | Inno Setup / WiX | Inno Setup 6 | 原项目已有 .iss 基础；脚本化、支持升级/卸载钩子 |
| 自动构建 | GitHub Actions | ✅ 已接 | `.github/workflows/build-installer.yml`（云端 Windows 全流程）+ 本地 `build\build_x64.ps1` |

## 五、如实披露的三个不可完全达成项

1. **TimescaleDB 无法随包分发（Windows）**
   - 官方不提供 Windows 二进制，社区版许可亦不允许再分发其二进制。
   - 已实现的替代：`measurements` 保持普通表并自动建 **BRIN 索引**（`app/deploy/schema.py`），时序查询功能不缺失、业务代码无需改动。
   - 恢复路径：客户自带 TimescaleDB 扩展文件放入 `pgsql\share\extension` 后，运行 `tools\Repair-Aims.ps1` 自动转为 hypertable。

2. **ARM64 原生：数据库无原生版**
   - PostgreSQL 无 Windows ARM64 官方构建。`build\build_arm64.ps1` 的行为：
     - 默认产出 `-arm64-emulation`（x64 仿真）包并明确命名；
     - `-Native` 开关在缺少 ARM64 数据库组件时**拒绝出包**。
   - 遵循计划书 8.3："不支持的组件必须明确标记，不得宣称已经兼容"。在 ARM64 真机验收通过前，不宣称原生支持。

3. **干净 Windows 验收未执行**
   - 本改造沙箱为 Linux。安装包编译（ISCC）、干净 Win11 安装/启动/卸载实测必须由构建机完成。
   - 已备好：`tools\Windows-Acceptance.ps1`（自动化 20+ 检查点，产出 JSON + Markdown 验收报告）。
