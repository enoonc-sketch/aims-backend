# AIMS 离线安装版 · 部署说明

本文面向实施/运维人员，说明 AIMS 在 Windows 上的部署结构、安装、升级、备份恢复与卸载。
终端用户请先看《用户手册》，排障请看《故障排查》。

---

## 1. 交付物与部署形态

| 交付物 | 说明 |
|---|---|
| `AIMS-<版本>-x64-Setup.exe` | Windows x64 离线安装包（单文件，含全部运行组件） |
| `AIMS-<版本>-arm64-Setup.exe` / `-arm64-emulation-Setup.exe` | ARM64 包，见 §8 |
| `build\*.ps1` | 构建脚本（在构建机上用，目标机不需要） |
| `tools\*.ps1` | 运维脚本（安装在 `%ProgramFiles%\AIMS\tools`） |
| `docs\` | 本套文档 |

目标机**不需要**预装 Python、Node.js、Docker、PostgreSQL，也不需要在安装过程中联网。

### 目录布局（程序与数据分离）

```
C:\Program Files\AIMS\                 程序（只读；升级时整体替换）
├─ AIMS.exe                            桌面启动器：托盘 + 服务编排
├─ AIMS-Backend\AIMS-Backend.exe       后端（FastAPI，含内嵌 Python 运行时）
│   └─ _internal\                      依赖库、DLL（含 llama.cpp）
├─ frontend.html                        单文件界面（JS/CSS 全部本地化）
├─ cores\                               诊断规则包 + SheetJS/Chart.js 本地副本
├─ pgsql\bin|lib|share                  内置 PostgreSQL 16 + pgvector
├─ tools\                               运维脚本
└─ rollback\<旧版本>\                   覆盖升级时保留的旧程序副本（可回滚）

C:\ProgramData\AIMS\                   数据（升级/卸载默认都不动）
├─ Config\aims.env                      生成的配置（含数据库口令，见 §5）
├─ Config\secrets.json                  JWT 密钥、数据库口令、初始管理员口令
├─ Database\                            PostgreSQL 集群（业务数据）
├─ Models\                              GGUF 模型（安装时从程序目录复制过来）
├─ Logs\                                启动器/后端/数据库/运维日志
├─ Uploads\                             上传与导入导出文件
└─ Backup\                              自动与手动备份（.dump + .meta.json）
```

> 为什么必须分离：`Program Files` 对普通用户只读，而应用要写数据；同时"覆盖安装"
> 只替换程序目录，业务数据一个字节都不会被碰到 —— 这是最省心的升级模型。

## 2. 组件清单

| 组件 | 版本 | 作用 | 部署方式 |
|---|---|---|---|
| Python 运行时 | 3.11/3.12（构建机） | 后端解释器 | PyInstaller 打进 EXE，目标机无感知 |
| FastAPI + Uvicorn | 见 `requirements-exe.txt` | HTTP API | 同上 |
| PostgreSQL | 16.x | 业务数据库 | 官方 zip 发行版，注册为 Windows 服务 `AIMSPostgreSQL` |
| pgvector | 0.8.x | 向量检索（知识库） | 扩展文件随包分发，`CREATE EXTENSION vector` |
| pg_trgm | 随 PG | 模糊检索 | 同上 |
| llama.cpp | llama-cpp-python 0.3.2 | 本地 GGUF 推理（CPU） | 打进后端 EXE |
| BGE-small-zh / Qwen2.5-0.5B | GGUF（可选） | Embedding / 对话 | 放 `cores\models`，安装时复制到 `Models\` |

| Inno Setup 6 | 构建期 | 生成安装程序 | 仅构建机需要 |

完整许可证见 `docs\依赖与许可证清单.md`、`LICENSES.txt`。

## 3. 安装

1. 以**管理员**身份双击 `AIMS-<版本>-x64-Setup.exe`（UAC 会提示）。
2. 选择安装目录（默认 `C:\Program Files\AIMS`）与附加任务：
   - **创建桌面快捷方式**（默认勾选）
   - **开机自动启动**（可选，写入当前用户 `HKCU\...\Run`，登录后最小化到托盘）
   - **把内置数据库注册为 Windows 服务**（默认勾选；取消则数据库随程序启动）
3. 安装程序自动执行：
   ```
   停止旧进程 → 复制程序文件 → deploy provision（建集群/建库/建表/装扩展/部署模型/首次备份）
   → deploy doctor（安装后健康检查）→ 创建快捷方式 → 注册版本信息
   ```
   这一步通常 1–3 分钟（取决于磁盘与模型大小）。
4. 完成页勾选"立即启动 AIMS"即可。**首次启动会显示初始化进度**，随后自动打开主界面。

### 无人值守安装（批量部署）

```powershell
.\AIMS-0.5.9-x64-Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- `
    /LOG=C:\temp\aims-install.log /TASKS=desktopicon,pgservice
```

或解压发行包后直接调用运维脚本（程序文件已就位时）：

```powershell
.\tools\install.ps1 -Service -ApiPort 8000      # 注册服务 + 初始化
.\tools\install.ps1 -NoSeed                     # 生产环境：不写演示数据
```

`install.ps1` 是幂等的：重复运行不会重建已有数据库，不会覆盖配置。

## 4. 启动与停止

| 操作 | 方式 |
|---|---|
| 启动（推荐） | 双击桌面 `AIMS` |
| 启动（无界面） | `AIMS.exe --no-browser` 或 `tools\Start-Aims.ps1 -NoWindow` |
| 停止 | 托盘菜单 → **退出**（会依次停后端、停本次启动的数据库） |
| 停止（脚本） | `tools\Stop-Aims.ps1 [-StopDatabase] [-Force]` |
| 查看状态 | 托盘菜单 → **生成诊断报告**，或 `tools\Get-AimsStatus.ps1` |

启动顺序由启动器保证：**PostgreSQL → AI 引擎自检 → 后端 → 打开主界面**。
后端是独立子进程；启动器异常退出时，后端会通过父进程看门狗在 3 秒内自行退出，
不会留下占着 8000 端口的孤儿进程（已实测）。

## 5. 配置

配置文件：`C:\ProgramData\AIMS\Config\aims.env`（UTF-8，`KEY=VALUE`）。

| 变量 | 默认 | 说明 |
|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg2://aims:***@127.0.0.1:55432/aims` | 内置数据库连接串 |
| `AIMS_PG_PORT` | `55432` | 数据库端口（被占用时安装程序自动顺延） |
| `PORT` | `8000` | 应用端口 |
| `AUTO_INIT_DB` / `AUTO_UPGRADE_SCHEMA` | `true` | 启动时建表 / 增量补列 |
| `EMBEDDING_STORAGE` | `auto` | `auto`/`vector`/`json`，见 §7 |
| `MODELS_DIR` | `...\Models` | 模型目录 |
| `AIMS_BACKUP_KEEP` | `14` | 备份保留份数 |
| `SECRET_KEY` | 随机 | JWT 签名密钥（**不要手工改**，改了所有会话失效） |

敏感信息不放在 `aims.env` 里，而在 `Config\secrets.json`（仅管理员可读：
`AIMSDBA`/`Administrators` + `Users` 组）。日志不会打印这些值。

修改配置后：

```powershell
# 以管理员身份，重启服务生效
.\tools\Stop-Aims.ps1
.\AIMS.exe
```

## 6. 备份与恢复

### 自动备份
- 每次启动：距上次成功备份超过 12 小时则自动备份一份（`reason=startup`）。
- 安装/升级/恢复/卸载前：强制备份（`post-install` / `pre-upgrade` / `pre-restore` / `pre-uninstall`）。
- 计划任务：`tools\Register-AimsTasks.ps1` 注册每日 03:00 备份（SYSTEM 身份，保留 14 份）。
- 自动清理：只保留最近 `AIMS_BACKUP_KEEP` 份非安全备份。

### 手动备份 / 恢复

```powershell
.\tools\backup.ps1                                   # 立即备份
.\tools\backup.ps1 -Reason pre-maintenance -Export E:\aims-backup   # 导出到U盘/网络盘
.\tools\restore.ps1                                  # 恢复最新（需输入 YES 确认）
.\tools\restore.ps1 -File aims-20260101-030000.dump  # 指定归档
```

备份产物是 `pg_dump -Fc` 归档 + 同名 `.meta.json`（版本、时间、大小、SHA-256）。
恢复流程：校验归档 → 自动安全备份 → 恢复 → 修正对象归属 → 自检。
**恢复会覆盖当前数据库**，所以必须先停止应用（脚本会检测并拒绝执行）。

已实测（Linux + PostgreSQL 16 + pgvector）：备份 → 写入标记数据 → 恢复 → 标记数据消失、
原有数据完整，恢复前的数据自动保存为 `pre-restore-*.dump`。

## 7. 覆盖升级

### 通过安装包（推荐）

直接运行新版本安装包。安装程序会：

1. 识别已安装版本（注册表 `DisplayVersion`）；
2. 停止正在运行的程序（提示确认）；
3. `deploy start` + `deploy backup --reason pre-upgrade`（备份失败会中止升级）；
4. 把旧程序复制到 `rollback\<旧版本>\`；
5. 覆盖程序文件 → `deploy provision --keep-config`（**只做加法**：建缺表、补缺列、装新扩展）；
6. `deploy doctor` 自检；
7. 启动并恢复使用。

### 通过脚本

```powershell
.\tools\upgrade.ps1              # 备份 → 停服 → 结构升级 → 自检 → 失败自动回滚
.\tools\upgrade.ps1 -PrepareOnly # 只做备份与停服（安装程序内部用法）
```

### 数据安全性

- 结构升级只 `CREATE TABLE IF NOT EXISTS` / `ALTER TABLE ADD COLUMN`，从不 `DROP`。
- 不修改任何已有业务表结构，不重命名、不合并。
- 自检不通过时可用 `rollback\<旧版本>` 程序副本 + `pre-upgrade` 备份回到原状。

## 8. ARM64 说明（请如实转述给客户）

| 事实 | 说明 |
|---|---|
| PostgreSQL 官方**没有** Windows ARM64 发行版 | 官方 Windows 二进制只有 x64（PG 16/17 均如此） |
| Windows 11 ARM64 可以运行 x64 程序 | 通过 Prism 仿真层 |
| 因此默认产出 `-arm64-emulation-Setup.exe` | 程序本体为 ARM64（若在 ARM64 构建机构建），数据库以 x64 仿真运行 |
| 性能影响 | 数据库进程约慢 10–25%；对单机低并发场景影响可接受，瓶颈通常在 AI 推理与磁盘 |

如果客户要求"纯原生 ARM64"，需要提供 ARM64 版 PostgreSQL（自行交叉编译或商业支持渠道），
然后 `.\build\build_arm64.ps1 -Native` 构建；脚本在缺少 ARM64 数据库时会**拒绝**生成
名为"arm64 原生"的安装包，避免交付一个名不副实的包。

**未在 ARM64 真机完成安装/启动/功能/卸载测试之前，不得对外宣称"已兼容 ARM64"。**

## 9. 卸载

| 方式 | 行为 |
|---|---|
| 设置 → 应用 → AIMS → 卸载 | 停服务、注销服务、删程序文件、清快捷方式；**保留** `C:\ProgramData\AIMS` |
| 卸载时选择"彻底删除数据" | 额外删除数据库、模型、配置、日志、备份（二次确认） |
| `tools\uninstall.ps1` | 同上（脚本版，`-Purge` 删除数据，`-Yes` 跳过确认） |

卸载后可以直接重装，历史数据仍在（已实测：卸载保留 → 重装 → `created_tables=0`，
业务数据行数不变）。

## 10. TimescaleDB 说明

需求书要求内置 TimescaleDB。实际情况与处理：

- **TimescaleDB 没有官方 Windows 构建**，也不提供可再分发的 Windows 二进制，
  因此安装包**不带**它。
- 代码里 `measurements` 表在有 TimescaleDB 时自动转 hypertable；没有时保持普通表，
  并自动建 **BRIN 索引**（`ix_measurements_time_brin`）—— 对按时间追加的时序数据，
  BRIN 是最接近 hypertable 的替代方案，查询性能损失通常 < 10%。
- 若客户后续获得 TimescaleDB 的 Windows 扩展文件，放进 `pgsql\share\extension` 与
  `pgsql\lib`，重新运行 `tools\Repair-Aims.ps1`，下次启动会自动 `CREATE EXTENSION timescaledb`
  并把 `measurements` 转成 hypertable，**无需改代码、无需迁移数据**。

相关自检项见 `Logs\doctor.json` 的 `Postgres extras` 说明。

## 11. 从源码构建

构建机：Windows 10/11 x64 + Python 3.10–3.12 + Inno Setup 6 + 联网。

```powershell
cd build
.\dependency_check.ps1 -ForBuild          # 先确认工具链
.\build_x64.ps1                           # 全流程：依赖→内置PG→打包→冒烟→编译安装包
.\build_x64.ps1 -UpdateLock               # 首次构建：记录下载文件 SHA-256
.\package_release.ps1 -Installer installer_output\AIMS-0.5.9-x64-Setup.exe
```

构建产物与报告：

```
dist\launcher\AIMS.exe                    启动器
dist\backend\AIMS-Backend\               后端（onedir）
installer_output\AIMS-<版本>-x64-Setup.exe
build_out\build-report-x64.json           版本/大小/SHA-256/PostgreSQL 版本/pgvector 是否内置
release\AIMS-<版本>\                      发行包（安装包 + 文档 + 脚本 + 校验和）
```

构建脚本会在以下情况**中止**，不会"带病出包"：

- 依赖检查失败（Python 版本、Inno Setup、源文件缺失、磁盘不足）
- 前端仍有外链 `script src`（离线会白屏）
- 后端/启动器 EXE 冒烟测试失败
- 内置下载文件的 SHA-256 与 `build\vendor.lock.json` 不一致

## 12. 端口与防火墙

| 端口 | 用途 | 暴露范围 |
|---|---|---|
| 8000（可改） | 应用 HTTP | 仅 `127.0.0.1`，默认不监听外网 |
| 55432（可改） | PostgreSQL | 仅 `127.0.0.1`，`pg_hba.conf` 显式 `reject` 其它来源 |

安装程序不会修改 Windows 防火墙规则（因为不需要）。如果要把 AIMS 开放给局域网同事访问，
需要自行配置反向代理（Nginx/IIS）并启用 TLS —— 那属于另一套安全设计，不在本安装包范围内。

## 13. 与旧版（绿色/SQLite 版）的关系

- 老版本的 `python run_standalone.py` 仍然可用（无 `pgsql` 目录时自动回落 SQLite）。
- 老版本的 `secrets.json` 在 `aims_data\` 下的，会被自动识别（只读兼容），
  下次写入口令时迁移到 `Config\`。
- 从 SQLite 迁移到 PostgreSQL 不在安装程序里自动完成：需要先把业务数据导出再导入。
  建议实施时按"新建库 + 导入台账/测点"的方式处理，避免自动迁移带来的不确定性。
