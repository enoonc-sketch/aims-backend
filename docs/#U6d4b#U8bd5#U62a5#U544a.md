## 4. 本轮发现并修复的缺陷

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | 端口被其它 PostgreSQL 占用时误判为"自己的库在跑" | 认证失败，报错莫名其妙 | 用 `postmaster.pid`（PID + 端口）判定归属；端口被占时给出可执行提示 |
| 2 | 恢复备份后表归属变成超级用户 | 应用"能打开但改不了"，日志满是 `permission denied` | 恢复后 `normalize_ownership()` 逐表/序列/视图改属主并补授权 |
| 3 | 删除被引用的设备返回 500 | 前端只显示"服务器内部错误" | 捕获 `IntegrityError` → 409 + 中文说明 |
| 4 | 内置 PG 使用系统默认 unix socket 目录 | 非管理员/非标准环境启动失败 | socket 固定到数据目录内 |
| 5 | 启动器被强杀后后端成孤儿 | 下次启动"端口被占用" | 父进程看门狗（3 秒内自退），已实测 |
| 6 | `init_db` 盲目调用 `create_hypertable` | 每次启动都打一整段 traceback，掩盖真问题 | 统一走 `deploy.schema`，缺扩展时用 BRIN 并只记一条说明 |
| 7 | `--root` 只能写在子命令前 | 安装程序/脚本调用易错 | 两种顺序都支持（`SUPPRESS` 默认值） |
| 8 | `secrets.json` 换目录后旧安装读不到 | 升级后会话失效、外部口令无法解密 | 新位置优先，旧位置只读兼容 |

## 5. 关键流程实测记录

### 5.1 备份 → 改数据 → 恢复

```
1. deploy backup --reason acceptance
   → aims-20261111-003307.dump（0.2 MB，0.1 秒）
2. 通过 API 新增设备 RESTORE-MARKER（备份之后写入）
3. 停止应用 → deploy restore latest --yes
   → 恢复前数据自动备份为 pre-restore-20261111-003336.dump
4. 校验：
   devices 总数 = 4
   RESTORE-MARKER 计数 = 0        ← 证明数据库真的被替换
   原有 4 台设备、3 篇知识文档全部存在
```

### 5.2 覆盖升级

```
deploy upgrade --keep-config
→ [schema] created_tables=0 added_columns=0 added_indexes=0
           hypertable=False vector_index=True brin=True
→ 完成，用时 0.5 秒
```
`created_tables=0` 说明**没有重建任何表**，是纯粹的原地升级。

### 5.3 孤儿进程防护

```
启动器 PID 39753 / 后端 PID 39763
kill -9 39753
→ backend exited after 3s
→ no orphan；端口 8000 已释放
```

## 7. 建议的验收步骤（在客户/测试机上）

1. 准备：全新 Win11 x64 虚拟机，**不装** Python/Node/Docker/PostgreSQL，**断网**。
2. 记录基线：`systeminfo`、已安装程序列表、`netstat -ano | findstr 8000`。
3. 安装：`AIMS-0.6.0-x64-Setup.exe`（观察 UAC、目录选择、进度、完成页）。
4. 启动：双击桌面图标 → 观察托盘图标、主界面打开、首屏数据。
5. 功能：托盘 → 生成诊断报告（应全绿）；`deploy selftest`（应 30/30）。
6. 备份恢复：按 `Windows-Acceptance.ps1` 第 3 节；恢复后核对业务数据。
7. 升级：装新版本包，确认"数据/配置/用户"都在，`pre-upgrade` 备份存在。
8. 卸载：确认无残留进程、服务已注销、`ProgramData\AIMS` 仍在。
9. 重装：确认历史数据可继续使用。
10. 断网复测：全程不联网，确认无任何外网请求（可用防火墙出站规则验证）。

## 8. 结论

- **与操作系统无关的全部逻辑已在真实 PostgreSQL 16 + pgvector 上验证通过**，

- **Windows 专属部分（安装包、服务、快捷方式、ARM64）尚未在目标环境执行**，
  因此本版本状态为：**功能就绪、待目标环境验收**，不标记为"正式交付"。
