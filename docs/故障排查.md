# AIMS 故障排查手册

原则：**先看自检，再看日志，最后才动手改**。
`tools\Get-AimsStatus.ps1` 一条命令能覆盖 90% 的现场问题。

```powershell
cd "C:\Program Files\AIMS\tools"
.\Get-AimsStatus.ps1          # 状态 + 逐项自检 + 最近日志
.\Get-AimsStatus.ps1 -Json    # 机器可读，便于远程收集
```

日志位置：`C:\ProgramData\AIMS\Logs\`

| 文件 | 内容 |
|---|---|
| `launcher.log` | 启动器：编排顺序、每步耗时、错误 |
| `backend.log` | 后端：启动、接口异常堆栈 |
| `provision.log` | 安装/升级/备份/恢复的每一步 |
| `ops.log` | 运维脚本执行记录 |
| `doctor.json` | 最近一次自检结果（逐项） |
| `selftest.json` | 最近一次功能自检（30 项真实请求） |
| `Database\pg_log\*.log` | PostgreSQL 自身日志 |

---

## 1. 安装阶段

| 现象 | 原因 | 处理 |
|---|---|---|
| 安装程序提示"需要 64 位 Windows" | 32 位系统 | 换 64 位系统；本产品不支持 x86 |
| 安装到一半失败，提示磁盘空间 | 小于 6 GB 可用 | 清理空间后重试；`Program Files` 与 `ProgramData` 需在同一盘或都留足空间 |
| 提示"AIMS 正在运行" | 托盘进程还在 | 选"是"让安装程序自动关闭；或先托盘退出 |
| 完成页提示"健康检查未产生报告" | provision 未执行完 | 看 `Logs\install-report.json` 与 `provision.log`；修好后运行 `tools\Repair-Aims.ps1` |
| 安装后启动报"配置文件缺失或不完整" | `Config\aims.env` 没生成或被删 | 管理员运行 `tools\install.ps1` 重新生成（不会动数据） |

## 2. 启动阶段

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击图标无反应 | 已在运行（单实例），或启动器被杀软拦 | 看托盘；把 `C:\Program Files\AIMS` 加入杀软排除项 |
| 弹窗"内置数据库启动失败（端口 55432）" | 端口被别的 PostgreSQL/程序占用 | 改 `Config\aims.env` 的 `AIMS_PG_PORT`（如 55433）后重试；或关掉占用程序 |
| 弹窗"数据集群未初始化" | `Database\` 为空或被删 | 有备份：`tools\restore.ps1`；无备份：`tools\install.ps1` 重建（数据不可恢复） |
| 弹窗"端口 8000 已被其它程序占用" | 应用端口冲突 | 改 `Config\aims.env` 的 `PORT`，或关闭占用程序 |
| 弹窗"后端服务启动后立即退出" | 通常是数据库认证失败/配置错误 | 看 `backend.log` 末尾 40 行；再跑 `deploy doctor` |
| 启动很慢（>2 分钟） | 首次启动要建表/写演示数据；或杀软全盘扫描 | 首次属正常；后续若仍慢，检查杀软与磁盘 |
| 界面白屏 | `frontend.html` 缺失或被改坏 | 覆盖安装（不动数据）；确认文件大小 > 200 KB |

## 3. 数据库

| 现象 | 原因 | 处理 |
|---|---|---|
| `password authentication failed for user "aims"` | `aims.env` 的 `DATABASE_URL` 与 `secrets.json` 不一致 | 运行 `tools\Repair-Aims.ps1`（会按口令重新同步角色） |
| `password authentication failed for user "aims_dba"` | 端口上跑的是**另一个** PostgreSQL（不是本机 AIMS 的） | `Get-AimsStatus.ps1` 看端口；改端口或停掉别的实例 |
| 日志出现 `must be owner of table ...` / `permission denied for table` | 恢复备份后对象归属仍是超级用户 | 已在 0.5.9 修复（恢复后自动 `normalize_ownership`）；旧版本可手工执行 `tools\Repair-Aims.ps1` |
| 日志出现 `function create_hypertable(...) does not exist` | 未安装 TimescaleDB（Windows 无官方构建） | **属预期**，会自动改用 BRIN 索引，功能不受影响（见部署说明 §10） |
| `pg_ctl: could not start server` | 见 `pg_log` 里第一行 FATAL | 常见：数据目录权限、端口占用、磁盘满、`postmaster.pid` 残留 |
| 磁盘占用持续增长 | WAL + 备份累积 | 降 `AIMS_BACKUP_KEEP`；`Database\pg_wal` 会在检查点后回收 |

## 4. AI

| 现象 | 原因 | 处理 |
|---|---|---|
| 自检里 "AI 推理引擎：未安装 llama.cpp" | 构建时没装 `llama-cpp-python` 轮子 | 功能自动降级为规则引擎；需要本地模型时用完整版安装包重建/重装 |
| 模型列表为空 | `Models\` 下没有 `.gguf` | 放入模型并 `tools\Repair-Aims.ps1`；或覆盖安装带模型的新包 |
| 问答很慢（>30 秒） | CPU 推理 + 线程数过高/过低 | `aims.env` 里 `AI_LOCAL_LLM_THREADS` 设为物理核心数（0=自动，上限 8） |
| 内存被打满 | 模型过大（如 7B Q4 需 ~6 GB） | 换更小的模型（0.5B/1.5B），或加内存 |

## 5. 备份与恢复

| 现象 | 原因 | 处理 |
|---|---|---|
| 备份命令报"数据库未运行" | 数据库服务被停 | 脚本会自动尝试启动；仍失败看 `pg_log` |
| 恢复被拒绝："AIMS 正在运行" | 应用仍在跑 | 托盘退出，或 `tools\Stop-Aims.ps1` |
| 恢复报"备份文件校验失败" | 归档损坏（拷贝中断/磁盘坏） | 换一份备份；用 `Backup\*.meta.json` 的 SHA-256 校验文件 |
| 恢复后自检有一堆 `permission denied` | 旧版本遗留问题 | 升级到 0.5.9+ 后重新恢复一次即可（会自动修归属） |
| 备份文件很小（几 KB） | 业务数据本就很少，或备份时连错了库 | 看 `.meta.json` 的 `database` 与 `size_bytes`；核对 `AIMS_PG_PORT` |

## 6. 卸载

| 现象 | 原因 | 处理 |
|---|---|---|
| 卸载提示文件被占用 | AIMS 还在运行 | 卸载程序会先尝试关闭；不行就 `Stop-Aims.ps1 -Force` |
| 卸载后数据库服务还在 | 服务注销失败（权限） | 管理员执行 `sc delete AIMSPostgreSQL` |
| 卸载后重装，数据还在吗 | **默认保留** | 这是设计；要清空用卸载时勾选"彻底删除"或 `uninstall.ps1 -Purge` |

## 7. 收集诊断信息（发给技术支持）

```powershell
cd "C:\Program Files\AIMS\tools"
.\Get-AimsStatus.ps1 -Json | Out-File "$env:TEMP\aims-status.json" -Encoding utf8
Compress-Archive -Path "$env:ProgramData\AIMS\Logs\*" -DestinationPath "$env:TEMP\aims-logs.zip" -Force
```

把 `aims-status.json` 与 `aims-logs.zip` 一起提供。
**注意**：`Config\secrets.json` 含口令，不要直接外发；日志里不含密钥。

## 8. 已知限制

1. **TimescaleDB 无 Windows 官方构建** → 用 BRIN 索引替代（见部署说明 §10）。
2. **ARM64 上数据库走 x64 仿真** → 未在真机验收前不得宣称原生支持。
3. **单机部署** → 应用与数据库只监听 `127.0.0.1`，不提供多机集群/远程访问配置。
4. **从 SQLite 老版本升级** → 不做自动数据迁移（表结构与序列差异大），需按台账/测点重新导入。
