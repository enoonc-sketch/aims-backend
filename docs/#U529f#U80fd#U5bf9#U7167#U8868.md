## 1. 打包前后对照

| 能力 | 改造前（源码/绿色版） | 改造后（桌面安装版） | 是否等价 |
|---|---|---|---|
| 运行方式 | `python run_standalone.py`（需装 Python） | 双击 `AIMS.exe`（内嵌运行时） | ✅ 功能一致，入口更简单 |
| 数据库 | SQLite 文件 或 外接 PostgreSQL | 内置 PostgreSQL 16（自动初始化） | ✅ 增强（并发、时序、向量） |
| 向量检索 | SQLite JSON + 应用层余弦 | pgvector ivfflat（缺失时自动回退 JSON） | ✅ 增强/等价 |
| 时序表 | 普通表 | 普通表 + BRIN；有 TimescaleDB 时自动 hypertable | ✅ 等价或增强 |
| 前端 | `frontend.html` 本地文件 | 同一文件，随包分发，本地依赖 | ✅ 完全一致 |

## 2. 数据库表

改造**没有删除、合并或重命名任何业务表**。表结构由 ORM 模型 + Alembic 迁移定义，
安装/升级时通过 `app/deploy/schema.py` 做**只增不减**的对账：

- 新增表：`CREATE TABLE IF NOT EXISTS`
- 新增列：`ALTER TABLE ... ADD COLUMN`（旧数据保留默认值）
- 新增索引：`CREATE INDEX IF NOT EXISTS`
- 绝不执行 `DROP TABLE` / `DROP COLUMN` / `RENAME`

实测（Linux + PostgreSQL 16）：全新安装建表 → 覆盖升级 `created_tables=0 added_columns=0`；
卸载保留数据后重装同样 `created_tables=0`，业务行数不变。

## 3. 新增的运维能力（不替代任何旧功能）

| 命令 | 作用 |
|---|---|
| `AIMS-Backend.exe deploy provision` | 初始化/修复本地部署（安装程序调用） |
| `deploy upgrade` | 覆盖升级（保留配置与数据） |
| `deploy status` / `doctor` | 状态与自检 |
| `deploy backup` / `backups` / `restore` | 备份、列出、恢复 |
| `deploy selftest` | 30 项真实业务请求的功能自检 |
| `deploy uninstall [--purge]` | 停服/注销/可选清库 |
| `deploy ai-probe` | 本地 AI 引擎与模型自检 |

启动器（`AIMS.exe`）新增：托盘菜单、单实例、服务编排、父进程看门狗、
开机自启、诊断报告、版本信息。

## 4. 未打包项及原因

| 项 | 原因 | 解决方案 |
|---|---|---|
| TimescaleDB | 官方无 Windows 构建，且不允许随意再分发 | 有扩展文件时自动启用；否则 BRIN 索引（见部署说明 §10） |
| Docker / docker-compose | 桌面单机部署不需要，且会引入虚拟化依赖 | 保留 `docker-compose.yml` 供服务端部署使用 |
| Node.js 前端构建链 | 前端是单文件 HTML，无需构建 | 保留源码，无需 Node |
| SQLite → PostgreSQL 自动迁移 | 表结构/序列差异大，自动迁移风险高 | 手工按台账/测点导入（文档说明） |
