# AIMS 1.0.0 安全审计报告

- **审计对象**：AIMS 设备智能运维系统 1.0.0（Windows 离线安装版）
- **审计时间**：2026-11-11
- **审计方式**：源码审计（阶段 0）+ 运行时动态审计（`tools/security_audit.py`）+ 依赖漏洞扫描（`pip-audit`）
- **审计环境**：Linux x86_64 / PostgreSQL 16.15 / Python 3.11.1（Windows 实机复核见第七节）
- **结论**：**高危 0 项、中危 0 项**；1 条环境相关提示（开发模式开放 `/openapi.json`，生产模式已关闭）

---

## 一、审计范围与方法

| 维度 | 方法 | 可复现命令 |
|---|---|---|
| 路由认证覆盖 | 静态遍历 FastAPI 路由表，检查每个端点的依赖链是否包含认证依赖 | `python tools/security_audit.py --static-only` |
| 未认证访问 | 对全部 GET 业务端点发无令牌请求，期望 401/403 | `python tools/security_audit.py --api ... --admin ... --admin-password ...` |
| 越权（RBAC） | 创建普通用户令牌，访问超管端点，期望 403 | 同上 |
| 令牌安全 | 篡改 JWT 载荷、构造 `alg=none` 令牌，期望拒绝 | 同上 |
| 暴力破解防护 | 连续错误登录，期望出现 429 | 同上 |
| 响应头 | 检查 CSP、`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` | 同上 |
| 依赖漏洞 | 对锁定清单 `requirements-exe.lock` 查 OSV/PyPI 漏洞库 | `pip-audit -r requirements-exe.lock --disable-pip --no-deps` |
| 供应链完整性 | 第三方二进制固定版本 + SHA-256 基线校验 | 见第五节 |

审计工具输出 JSON（`security-audit.json`），有高危项时进程退出码非 0，可直接卡住发布流水线。

## 三、本次审计发现并修复的问题

### 3.1 普通用户可枚举全部用户（高危，已修复）

- **现象**：`GET /api/v1/system/users` 只要求"已登录"，普通用户返回 200，可拿到所有用户名、邮箱、`is_superuser` 标志、最后登录时间。
- **影响**：直接暴露攻击面（哪些账号是管理员），并为进一步的定向爆破提供目标清单。
- **修复**：依赖改为 `get_current_superuser`（`app/api/v1/system.py`）。
- **回归**：`tests/test_rbac_admin_endpoints.py::test_user_list_requires_superuser`。

### 3.2 普通用户可触发模型目录扫描（高危，已修复）

- **现象**：`POST /api/v1/ai/cores/scan-local` 只要求"已登录"，普通用户可让后端扫描模型目录并写入模型注册表。
- **影响**：与"模型加载 / 卸载 / 删除仅管理员"的既定策略不一致，普通用户可改变本机可用模型集合。
- **修复**：依赖改为 `get_current_superuser`（`app/api/v1/ai.py`）。
- **回归**：`tests/test_rbac_admin_endpoints.py::test_model_scan_requires_superuser`。

> 附带确认：`GET /system/settings`、`GET /system/components` 仍对普通用户开放——前端需要读站点名与组件版本，且这些内容不含密钥。收紧权限不能顺手把用户要用的只读能力关掉（`test_read_only_settings_stay_available_to_users` 守住这一点）。

### 3.3 依赖漏洞：pypdf 3.17.4 有 103 项已知漏洞（高危，已修复）

- **现象**：`pip-audit` 对锁定清单扫描，50 个依赖中唯一命中是 `pypdf 3.17.4`，累计 103 条漏洞记录（PYSEC/CVE，多为畸形 PDF 触发的无限循环、内存耗尽、递归溢出），修复版本一路到 6.21.4。
- **影响**：PDF 故障报告由用户上传，属于不可信输入，正好是这些漏洞的触发面。
- **修复**：升级到 `pypdf 7.0.1`（`requirements.txt` / `requirements-exe.txt` / `requirements-exe.lock` 三处同步）。
- **验证**：PDF 解析 6 个测试全部通过（含真实 PDF 的标签提取与异常 PDF 拒绝）；复扫结果 **50 个依赖、0 个有漏洞**。

### 3.4 重复导入导致 HTTP 500（中危 / 可用性，已修复）

- **现象**：重复导入同一份 CSV，主键 `(time, device_id, component_name)` 冲突抛 `UniqueViolation`，接口返回 500 并输出堆栈。
- **影响**：不构成越权，但把"数据重复"暴露成"服务器错误"，且堆栈可能泄漏内部结构；现场补录、断线重发、重导修正都会命中。
- **修复**：写入层改幂等 `INSERT ... ON CONFLICT (…) DO UPDATE`（PostgreSQL / SQLite 双分支），并在接口层兜住其它约束冲突返回 409 + 中文说明。
- **回归**：`tests/test_measurement_import_idempotent.py`（重复导入不增行、值取最新；时间窗部分重叠只更新重叠点）。

## 四、动态审计结果明细

| 检查项 | 结果 |
|---|---|
| 默认弱口令 `admin/admin123` | ✅ 登录失败（未创建默认管理员） |
| 错误口令返回码 | ✅ 401（不区分"用户不存在/口令错误"，避免账号枚举） |
| JWT 载荷篡改（提权 `is_superuser`） | ✅ 拒绝（签名校验生效） |
| `alg=none` 令牌 | ✅ 拒绝（算法固定 HS256） |
| 未认证访问 194 个受保护端点 | ✅ 全部 401 |
| 普通用户访问超管端点（用户列表/审计日志/用户创建/外部源/模型扫描/模型删除） | ✅ 全部 403 |
| 安全响应头 | ✅ CSP、`X-Content-Type-Options: nosniff`、`X-Frame-Options`、`Referrer-Policy` 均存在 |
| 登录失败节流 | ✅ 第 6 次触发 429（按用户名 5 次 / 15 分钟） |
| `/openapi.json` | ⚠ 开发模式可访问；`APP_ENV=production` 时 `docs_url`/`openapi_url` 均为 `None`（`app/main.py:155-157`），生产关闭 |

> 关于 429：审计脚本用不存在的用户名试 6 次，只触发"按用户名"锁定，不打满 IP 配额（20 次/15 分钟），避免审计把后续测试全锁死——这是脚本设计约束，也是本次审计踩过的坑。

## 五、供应链与完整性

| 项 | 状态 |
|---|---|
| 依赖锁定 | `requirements-exe.lock` 精确版本；SBOM 见 `docs/sbom-1.0.0.cdx.json`（CycloneDX 1.4，50 组件） |
| 第三方二进制（PostgreSQL / pgvector） | 固定版本 + `build/vendor.lock.json` SHA-256 基线，哈希不符立即中止构建 |
| 校验基线策略 | **没有基线就报错**，必须显式 `-UpdateLock` 建立并入库（防止"第一次下载什么就信任什么"） |
| 发布包校验和 | `build/package_release.ps1` 生成 `SHA256SUMS.txt` + `release-manifest.json` |
| 代码签名 | 构建脚本已内置签名+验签环节（`Sign-AimsFile`，顺序由测试锁死）；**尚无企业证书，当前产物未签名**。证书到位后按 `docs/安装说明.md` 第七节配置环境变量即可 |

## 六、防护措施清单（本次审计确认仍然有效，不得回退）

- 口令策略（长度/复杂度/常见口令拒绝）、bcrypt 哈希
- 刷新令牌轮换 + 旧令牌失效，条件 UPDATE 防并发重复使用
- 登录节流（用户名 5/15min、IP 20/15min）+ 审计日志记录 `AUTH_LOGIN_BLOCKED`
- 全局限流中间件（认证 20/min、业务 600/min，429 带 `Retry-After`）
- SSRF 防护：公网 scheme 白名单 + 私网/环回/链路本地/元数据 IP 拒绝，已登记网关与 TAG 例外放行
- 上传防护：扩展名白名单 + magic 嗅探 + PDF 危险对象（`/JavaScript`、`/Launch`、`/OpenAction` 等）拒绝 + 大小上限 64 MB
- 密钥分离：HKDF 派生 jwt / refresh / fernet 子密钥，旧密文可回退解密
- 数据归属：报警确认人取认证身份，不接受客户端传入（防伪造）
- 模型删除防护：超管 + `?confirm=true` + 激活中拒绝 + 规则包拒绝 + 目录外路径拒绝
- 卸载默认保留用户数据（数据目录标记 `uninsneveruninstall`，删除需二次确认）

## 七、尚未覆盖 / 后续动作

1. **Windows 实机复核**：本报告在 Linux + PostgreSQL 16.15 上完成。Windows 安装版需在干净 Win11 上重跑 `tools/security_audit.py`（安装后服务监听 127.0.0.1:8000），重点复核生产模式 `APP_ENV=production` 下的 `/openapi.json` 关闭与 Windows 服务账户权限。
2. **代码签名**：当前安装包未做 Authenticode 签名，SmartScreen 会提示"未知发布者"。构建链已自动化（主程序→安装包→校验和 的正确顺序，且签名后用 `signtool verify` 复核，未签名会在发行清单里如实标记 `code_signing.signed=false`），缺的只是证书。
3. **渗透测试**：本报告为"已知攻击面 + 自动化回归"层面的审计，未做人工渗透（业务逻辑越权组合、CSRF 场景、文件解析模糊测试）。建议发布前安排一次第三方渗透。
4. **SBOM 时效**：SBOM 随依赖变更重建，命令见 `docs/管理员手册.md`。
